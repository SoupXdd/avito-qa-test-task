## Задание 2.1. API

[Тест-кейсы](TESTCASES.md) · [Журнал запросов к ИИ](PROMPTS.md)

### Запуск тестов

Нужны JDK 21 и интернет. После клонирования запусти из корня репозитория:

```bash
./task2/gradlew -p task2 apiTest
```

Gradle Wrapper скачает зависимости. Тесты обращаются к `https://qa-internship.avito.com`, сами регистрируют аккаунты и получают токены. Для запросов установлены таймауты подключения 10 секунд и чтения 30 секунд. Очистка удаляет тестовые объявления. Удаление аккаунтов в сценариях не предусмотрено. Отчет Gradle появится в `task2/build/reports/tests/apiTest/index.html`.

Для проверки очистки, разбора ошибок и фикстур API-11 и API-12 без обращения к стенду:

```bash
./task2/gradlew -p task2 apiTest \
  --tests 'qa.api.ItemCleanupTest' \
  --tests 'qa.api.ApiErrorBodyTest' \
  --tests 'qa.api.Api12FixtureTest' \
  --tests 'qa.api.AvitoApiTest.*Api11Fixture*'
```

### Allure

Чтобы получить Allure из одного прогона, выполни из корня:

```bash
./task2/gradlew -p task2 clean apiTest
./task2/gradlew -p task2 allureReport -x apiTest -x test -x uiTest
./task2/build/allure/commandline/bin/allure open task2/build/reports/allure-report/allureReport
```

Allure можно собрать и после падения тестов. В шаге запроса видны HTTP-метод, путь и статус ответа. Если запрос прервался исключением, в шаге указан его тип.

Вложение **API failure diagnostics** показывает последовательность запросов упавшего теста. При расхождении HTTP-статусов в нём также видны ожидаемый и фактический код. Заголовки и тела запросов и ответов во вложение не попадают.

Скачай [пример отчёта](allure-example.zip), распакуй архив и открой `index.html`. В примере есть намеренно упавшая локальная проверка, чтобы показать вложение.

### Стиль Java

Из корня репозитория:

```bash
./task2/gradlew -p task2 checkstyleTest spotlessCheck
./task2/gradlew -p task2 spotlessApply
```

Первая команда проверяет стиль, вторая форматирует Java-файлы. Spotless заменяет табы в отступах пробелами (четыре на таб), убирает пробелы в конце строк и добавляет перевод строки в конце файла. Checkstyle проверяет табы, перевод строки в конце файла, неиспользуемые импорты, импорты со звёздочкой и обязательные фигурные скобки.

### GitHub Actions

В GitHub открой **Actions → API Tests → Run workflow**. По окончании скачай архив `api-results-…` из **Summary** и открой `reports/allure-single/index.html` в браузере. В архиве также есть HTML-отчет Gradle и JUnit XML. Если тесты падают, статус запуска остается красным, а отчеты все равно собираются из доступных результатов.

### Покрытие

- Сквозная автоматизация покрывает 22 из 25 документированных кейсов. API-21 покрыт частично. Число запусков в отчете также учитывает параметризованные варианты, дополнительные сценарии и локальные проверки. [Соответствие кейсов и методов](TESTCASES.md#соответствие-автотестам)
- Сквозной тест проходит от регистрации и входа до удаления объявления. Он сверяет сохраненное объявление и статистику обеих версий, затем проверяет `404` при чтении удаленной записи.
- В [API-21](TESTCASES.md#1-api-21) проверяется удаление объявления. Проверка статистики после удаления пропускается до уточнения контракта.
- [API-11](TESTCASES.md#1-api-11) и [API-12](TESTCASES.md#1-api-12) имеют локальные проверки результата на фикстурах. Сквозное покрытие остается открытым. В API-11 вручную подтвержден отказ создания.
