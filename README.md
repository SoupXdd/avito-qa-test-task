## Быстрый старт

Нужны **JDK 21** и интернет для загрузки зависимостей и запросов к стенду. Выполни из корня репозитория:

```bash
./task2/gradlew -p task2 apiTest
```

Gradle Wrapper скачает зависимости. Тесты регистрируют собственных продавцов с уникальными логинами, получают Bearer-токены через API и удаляют созданные объявления. Сценарии работают независимо. Тестовые аккаунты остаются на стенде.

| Параметр | Значение |
| --- | --- |
| Стенд | `https://qa-internship.avito.com` |
| Таймауты | 10 с на подключение, 30 с на чтение |
| Отчёт Gradle | `task2/build/reports/tests/apiTest/index.html` |
| Стек | Java 21, JUnit 5, Rest Assured, Gradle, Allure |

<details>
<summary>Локальные проверки без запросов к стенду</summary>

```bash
./task2/gradlew -p task2 apiTest \
  --tests 'qa.api.ItemCleanupTest' \
  --tests 'qa.api.ApiErrorBodyTest' \
  --tests 'qa.api.AuthClientTest' \
  --tests 'qa.api.ItemClientTest' \
  --tests 'qa.api.Api12FixtureTest' \
  --tests 'qa.api.AvitoApiTest.*Api11Fixture*'
```

Команда проверяет очистку, разбор ошибочных ответов, исключение токена из сообщений об ошибках, извлечение UUID и логику проверок владельца на фикстурах.

</details>

## Покрытие API

**22 из 25 кейсов полностью автоматизированы.** Набор охватывает регистрацию, вход, доступ к защищённым ручкам, создание и чтение объявлений, списки продавцов, статистику и удаление. [Карта покрытия](TESTCASES.md#соответствие-автотестам)

Сквозной сценарий `shouldCompleteItemLifecycle` проходит от регистрации и входа до удаления объявления. Он сверяет сохранённые поля и статистику обеих версий, затем проверяет `404` при повторном чтении удалённой записи. [Код сценариев](task2/src/test/java/qa/api/AvitoApiTest.java)

| Кейс | Что подтверждено | Что осталось |
| --- | --- | --- |
| [API-11](TESTCASES.md#1-api-11) | На стенде вручную подтверждён отказ `400`. Есть локальная проверка результата | Чтение обоих списков и отсутствие записи на стенде |
| [API-12](TESTCASES.md#1-api-12) | Обе ветки результата проверяются на фикстурах | Сквозной прогон и связь создания с чтением по UUID |
| [API-21](TESTCASES.md#1-api-21) | Автотест проверяет удаление объявления и сохранность второй записи | Контракт статистики после удаления. Обе версии вернули `200`, проверка отключена до уточнения |

При повторном удалении в API-22 Bruno показал HTTP `404` и поле `"status": "500"` в JSON. Значение этого поля требует уточнения. [API-22](TESTCASES.md#1-api-22)

В Allure видны метод, путь и HTTP-статус каждого запроса. При сетевом сбое шаг показывает тип исключения. Вложение **API failure diagnostics** перечисляет запросы упавшего теста и показывает первую пару ожидаемого и фактического статусов, если её содержит сообщение Rest Assured. [Пример Allure с диагностическим вложением](allure-example.zip)

<details>
<summary>Собрать Allure локально</summary>

```bash
./task2/gradlew -p task2 clean apiTest
./task2/gradlew -p task2 allureReport -x apiTest -x test -x uiTest
./task2/build/allure/commandline/bin/allure open task2/build/reports/allure-report/allureReport
```

Команду сборки отчёта можно выполнить после падения тестов. Для просмотра демонстрационного архива распакуй его и открой `index.html`. В примере одна локальная проверка падает намеренно, чтобы показать вложение.

</details>

### GitHub Actions

Открой **Actions → API Tests → Run workflow**. На `master` запуск также срабатывает при изменении исходников, конфигурации или файлов сборки `task2`, а также самого workflow. В том же запуске проверяется стиль Java.

В **Summary** скачай архив `api-results-…` и открой `reports/allure-single/index.html`. В архив также входят HTML-отчёт Gradle и JUnit XML. При падении шаг сборки отчёта использует доступные результаты, а запуск сохраняет статус ошибки. [Workflow API Tests](.github/workflows/api-tests.yml)

## Стиль Java

```bash
./task2/gradlew -p task2 checkstyleTest spotlessCheck
./task2/gradlew -p task2 spotlessApply
```

Первая команда проверяет стиль, вторая форматирует файлы. Checkstyle проверяет импорты, фигурные скобки, табуляцию и перевод строки в конце файла. Spotless заменяет табы в отступах четырьмя пробелами, удаляет пробелы в конце строк и добавляет финальный перевод строки. [Правила Checkstyle](task2/config/checkstyle/checkstyle.xml) · [Настройки Spotless](task2/build.gradle)
